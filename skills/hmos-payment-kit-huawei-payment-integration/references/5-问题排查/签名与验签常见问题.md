# 签名与验签常见问题

## TP-SIGN-001: 为什么会报 `INVALID_SIGNATURE`？

优先检查：

- 是否错误地把 `sign` 字段也参与了签名。
- 字段是否按 ASCII 排序。
- 空字符串是否被错误忽略。
- 使用的私钥、公钥、`authId` 是否匹配当前环境。

## TP-SIGN-002: 为什么本地调试正常，线上失败？

优先检查：

- 线上是否换了证书但代码未同步。
- 沙盒与生产的公钥或域名是否混用。
- 是否对同一个订单重复发起请求。

## TP-SIGN-003: 为什么回调一直验签失败？

优先检查：

- 是否直接拿解析后的对象去验签，而不是原始回调报文。
- 是否使用了错误的华为支付回调公钥。
- 是否在代理层改写了请求体。

## TP-SIGN-004: SDK 生产环境 SecureRandom 熵阻塞

- **业务场景**: 基础支付（APP预下单）/ 签名验签
- **错误码/现象**: 生产环境预下单接口响应缓慢，CPU 正常但签名耗时数秒

**常见原因**
Java SDK 在 Linux 容器（特别是 `/dev/random` 熵不足的环境）中使用 `SecureRandom`
生成随机数时，会阻塞等待熵源。开发环境正常，生产环境（尤其是高并发或容器化部署）出现阻塞。

**解决步骤**

1. 可尝试在 JVM 启动参数中添加 `-Djava.security.egd=file:/dev/./urandom`（非必定有效）
2. 或在代码中显式设置 `SecureRandom.getInstanceStrong()` → 改用 `new SecureRandom()`，包含几处引用：payClient.buildOrderStr(response.getPrepayId())方法、默认http客户端工具类DefaultPetalPayClient构建及发送请求方法请求头payMercAuth中用了安全随机数。
3. 容器化部署时确保 `/dev/urandom` 可读
4. 监控签名耗时，确认阻塞已消除

**官方文档**

- [Java SecureRandom 文档](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/security/SecureRandom.html)

## TP-SIGN-005: bodySign 加签内容与字段顺序

- **业务场景**: 基础支付（APP预下单）/ 签名验签
- **错误码/现象**: 预下单返回 `INVALID_SIGNATURE`，但本地验签通过

**常见原因**
`bodySign` 加签内容必须为请求体所有字段（除 `sign` 字段外）按 ASCII 码升序拼接后的字符串。常见错误：字段顺序错、空字符串被忽略、
`sign` 字段被误纳入加签、嵌套对象未展平。

**解决步骤**

1. 确认加签字段为请求体所有字段（除 `sign`）
2. 字段名按 ASCII 码升序排序
3. 空字符串 `""` 也需参与签名（不可忽略）
4. 嵌套对象展平为 `key.subkey=value` 格式
5. 使用官方 SDK 的签名工具类，避免手写拼接
6. 对比官方 demo 的签名原文与本地签名原文

**官方文档**

- [签名生成规则](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/payment-signature)

## TP-SIGN-006: signType 缺失（默认 SM2 vs RSA）

- **业务场景**: 基础支付 / 签名验签
- **错误码/现象**: 请求中未传 `signType`，返回 `INVALID_SIGNATURE` 或验签失败

**常见原因**
`signType` 缺失时，平台默认按 SM2 算法验签。若商户实际使用 RSA 算法签名（或反之），会导致验签失败。部分老商户仍使用 RSA，新商户默认SM2。

**解决步骤**

1. 确认商户证书算法（RSA 或 SM2）
2. 请求中显式传递 `signType`（`RSA` 或 `SM2`）
3. 确保签名算法与商户证书算法一致
4. 回调验签也需使用对应算法
5. 参考官方证书配置指南

**官方文档**

- [证书配置指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/payment-certificates-config)

## TP-SIGN-007: 服务商误调直连商户预下单接口

- **业务场景**: 基础支付（APP预下单）/ 签名验签
- **错误码/现象**: 服务商模式调用预下单返回 `INVALID_SIGNATURE` 或 `INVALID_MERCNO`

**常见原因**
直连商户预下单接口和服务商预下单接口的签名规则、加签字段、接口路径不同。服务商误调直连接口会导致签名校验失败或商户号不匹配。

**解决步骤**

1. 确认商户类型：直连商户 vs 服务商
2. 直连商户调用 `/api/v2/aggr/preorder/create/app`（直连版）
3. 平台类商户、服务商调用 `/api/v2/partner/aggr/preorder/create/app`（服务商版）
4. 核对接口路径与签名规则
5. 服务商版需传递 `spMercNo`/`subMercNo`，加签字段包含这两个字段

**官方文档**

- [直连商户预下单](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/payment-prepay)
- [服务商预下单](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/payment-agent-prepay)
