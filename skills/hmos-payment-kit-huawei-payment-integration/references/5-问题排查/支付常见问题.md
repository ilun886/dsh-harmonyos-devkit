# 支付常见问题

## TP-PAY-001: 为什么客户端拉起失败？

优先检查：

- 客户端类型是否判断错了。
- `orderStr` 是否来自真实服务端。
- `appId`、`client_id`、`bundleName` 是否与 AGC 配置一致。

## TP-PAY-002: 为什么预下单成功率很低？

优先检查：

- 订单号是否重复。
- `callbackUrl` 是否公网 HTTPS。
- 沙盒与生产配置是否混用。

## TP-PAY-003: 为什么客户端显示成功，但订单没更新？

原因：

- 客户端结果不是最终交易结果。

处理：

- 先检查服务端是否收到回调。
- 未收到回调时，再查网络可达性与回调配置。
- 需要使用查单接口兜底。

## TP-PAY-004: 为什么上线后突然失败？

优先检查：

- 证书、公钥、域名是否完成生产切换。
- 是否遗留沙盒标识。
- 是否变更了 `appId`、商户号或回调地址。

## TP-PAY-005: 模拟器不支持拉起支付收银台

- **业务场景**: 基础支付（APP调起）
- **错误码/现象**: 在鸿蒙模拟器上调用 `paymentService.requestPayment` 无法拉起华为支付收银台

**常见原因**
华为支付收银台依赖 HMS Core Payment Kit 的真实运行环境，模拟器未内置 Payment Kit，无法拉起真实收银台。模拟器仅可用于 UI 调试和参数校验，不能用于支付链路联调。

**解决步骤**

1. 改用真机（鸿蒙 HarmonyOS 3.0 及以上）调试支付链路
2. 真机需安装 HMS Core 并登录华为账号
3. 模拟器仅用于校验 `orderStr` 解析、参数拼接等非支付链路逻辑
4. 若无真机，通过沙盒环境预下单接口验证服务端逻辑

**官方文档**

- [HarmonyOS Payment Kit 接入指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/payment-introduction)

## TP-PAY-006: paymentService.requestPayment 闪退

- **业务场景**: 基础支付（APP调起）
- **错误码/现象**: 调用 `paymentService.requestPayment` 时应用闪退或无响应

**常见原因**
闪退常见根因：`orderStr` 为空或格式错误、`appId` 与 AGC 配置不一致、Payment Kit 版本过低、未声明所需权限、`bundleName` 与 AGC 注册不一致。

**解决步骤**

1. 检查 `orderStr` 是否来自服务端真实预下单响应，非空且为完整字符串
2. 确认 `appId`、`client_id`、`bundleName` 与 AGC 配置一致
3. 在 `module.json5` 中声明 `ohos.permission.PAYMENT` 权限
4. 查看 HiLog 过滤 `Payment` 标签获取崩溃堆栈

**官方文档**

- [HarmonyOS Payment Kit 接入指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/payment-introduction)

## TP-PAY-007: HarmonyOS NEXT vs 历史版本兼容

- **业务场景**: 基础支付（APP调起）
- **错误码/现象**: 应用在HarmonyOS NEXT与历史版本（HarmonyOS 3.1/4.0及以下版本）机型上支付行为不一致

**常见原因**
HarmonyOS NEXT版本与历史版本机型对 Payment Kit 的调用方式存在差异：HarmonyOS NEXT版本使用 ArkTS API，历史版本机型可能不一致。SDK版本与系统版本不匹配会导致接口调用失败。

**解决步骤**

1. 确认目标机型系统版本（HarmonyOS NEXT版本 vs 与历史版本）
2. HarmonyOS NEXT版本使用 ArkTS Payment Kit API
3. 确认历史版本机型是否需要按HarmonyOS 3.1/4.0及以下版本处理
4. 在 `build-profile.json5` 中配置 `compatibleSdkVersion` 与目标机型匹配
5. 测试覆盖两类机型

**官方文档**

- [HarmonyOS Payment Kit 版本说明](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/payment-error-code)

## TP-PAY-008: 应用校验不通过（appId/orderStr.app_id/p7b证书app-identifier 三者一致性)

- **业务场景**: 基础支付（APP调起）
- **错误码/现象**: 端侧拉起支付失败，返回 `INVALID_APPID` 或 `1001930001` 或弹框报错 “应用信息校验不通过”

**常见原因**
`appId/subAppId`（预下单传递）、`app_id`（orderStr参数构建）、签名证书（`.p7b` 证书）中声明的 `app-identifier` 三者必须一致。任一不匹配都会导致 Payment Kit 拒绝拉起收银台。 
端校验：orderStr-app_id、调试证书.p7b文件内容中“app-identifier，云校验：orderStr-app_id、预下单传递的appId或spAppId或subAppId。
即：orderStr-app_id、 客户端调试证书.p7b文件内容中“app-identifier、（预下单appId（直连商户】或spAppId【平台、服务商户】或subAppId【子商户、特约商户】）这三个应用ID需要保持一致

**解决步骤**

1. 登录 AGC 查看应用 `app-identifier`
2. 确认 `.p7b` 证书中 `bundleName` 与 `app-identifier` 一致
3. 预下单请求中传递的 `subAppId` 与 AGC `app-identifier` 一致
4. 若使用服务商模式，`spAppId` 和 `subAppId` 均需校验一致性
5. 重新生成 `.p7b` 证书（若 `bundleName` 变更）

**官方文档**

- [应用签名与证书配置](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/payment-certificates-config)

## TP-PAY-009: 三方支付收银台展示控制 reserved.selectPayType

- **业务场景**: 基础支付（APP调起）
- **错误码/现象**: 三方支付方式未在收银台展示，或返回 `INSUFFICIENT_PERMISSION`

**常见原因**
使用三方支付（如微信、支付宝）时，需在拉起收银台参数orderStr的 `reserved.selectPayType` 中声明支付方式，且appId需在已申请开通对应三方支付权限。
未声明或未开通会导致支付方式不展示。

**解决步骤**

1. 在拉起收银台参数PaymentInfo.extraInfo（纯三方模式）、orderStr扩展参数reserved.selectPayType（混合模式）中传递三方支付方式标识，
2. 商户平台确认已开通对应三方支付权限
3. 确认 `appId` 与商户号的绑定关系包含三方支付能力
4. 端侧收银台将展示已开通且已声明的方式

**官方文档**

- [三方支付接入指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/payment-common-pay-connect)

## TP-PAY-010: 通用收银台 vs 三方支付接口选择

- **业务场景**: 基础支付（APP调起）
- **错误码/现象**: 商户不确定使用通用收银台接口还是三方支付接口

**常见原因**
通用收银台支持华为钱包余额、绑卡、平台券等多种支付方式；三方支付接口仅支持单一支付方式（如微信、支付宝）。商户需根据业务场景选择。

**解决步骤**

1. 默认使用通用收银台（覆盖华为生态支付方式）
2. 如需接入微信/支付宝，使用三方支付接口
3. 两者可并存，通过 `reserved.selectPayType` 控制展示
4. 参考官方接入指南确认接口路径

**官方文档**

- [HarmonyOS Payment Kit 接入指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/payment-common-pay-connect)

## TP-PAY-011: APP/元服务支付流程一致性

- **业务场景**: 基础支付（APP调起）
- **问题概述**: 商户不确定 APP、元服务三种场景的支付流程是否一致

**常见原因**
拉起收银台接口一致，服务端预下单接口不同，其他接口逻辑可复用。

**解决步骤**

1. 服务端预下单预下单接口不同
2. 端统一使用 `paymentService.requestPayment` 拉起

**官方文档**

- [APP/元服务预下单接入](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/payment-agent-prepay)

## TP-PAY-012: 特约商户号预下单 spMercNo/subMercNo 传法

- **业务场景**: 基础支付（APP预下单）
- **错误码/现象**: 服务商模式下预下单返回 `INVALID_MERCNO` 或子商户订单数据异常

**常见原因**
服务商模式下预下单需同时传递 `spMercNo`（服务商商户号）和 `subMercNo`（特约商户号）。若传反、漏传或使用直连商户号，会导致商户号校验失败。

**解决步骤**

1. 服务商模式：`spMercNo` = 服务商商户号，`subMercNo` = 特约商户号
2. 直连模式：仅传 `mercNo`，不传 `spMercNo`/`subMercNo`
3. 确认 `appId` 与 `spMercNo` 的绑定关系
4. 在商户平台核对服务商与特约商户的绑定关系

**官方文档**

- [预下单接口](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/payment-preorder)

## TP-PAY-013: 联盟二级商户不支持直接接入华为支付

- **业务场景**: 基础支付（APP预下单）
- **错误码/现象**: 通过华为开发者联盟进件的二级商户直接调用预下单失败

**常见原因**
联盟进件的二级商户（特约商户）不能直接接入华为支付，必须通过服务商模式接入。二级商户无独立证书上传入口，证书由服务商统一管理。

**解决步骤**

1. 确认商户入网渠道：联盟进件 → 二级商户
2. 二级商户必须通过服务商模式接入
3. 服务商在商户平台为二级商户上传证书
4. 预下单使用服务商模式传参（`spMercNo` + `subMercNo`）
5. 如需独立接入，重新在商户平台入网为直连商户

**官方文档**

- [商户入网申请](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/payment-merc-regist-apply)

## TP-PAY-014: 预下单接口访问不通（商户内网限制）

- **业务场景**: 基础支付（APP预下单）
- **错误码/现象**: 服务端调用预下单接口超时或网络不通

**常见原因**
商户服务器内网防火墙未放行华为支付域名，或未配置出网代理。
华为支付预下单接口域名为 `petalpay-developer.cloud.huawei.com.cn`（生产）/`petalpay-developer-sandbox.cloud.huawei.com.cn`（沙盒），需确保网络可达。

**解决步骤**

1. 确认商户服务器可访问 `petalpay-developer.cloud.huawei.com.cn`/`petalpay-developer-sandbox.cloud.huawei.com.cn`
2. 内网环境配置出网代理或防火墙白名单
3. 使用 `curl` 或 `telnet` 测试域名连通性
4. 确认使用生产域名（非沙盒域名）
5. 检查 DNS 解析是否正常

**官方文档**

- [预下单接口](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/payment-preorder)
