# 平台类合单接入指南

## 适用场景

- 一个支付动作下存在多个子订单。
- 由平台类商户统一发起支付。
- 需要把支付结果再映射回多个业务子订单。

## 最小闭环

1. 确认平台类商户身份和子订单结构。
2. 服务端发起平台类合单预下单。
3. 服务端返回 `orderStr` 给客户端。
4. 客户端拉起支付。
5. 服务端处理合单回调并按子订单维度落业务。

## 关键规则

- 合单不是把基础支付简单复制一遍，回调和订单关联关系都更复杂。
- 预下单前必须先明确平台商户、子订单商户和资金归属关系。
- 合单结果要和子订单关系一起做幂等。

## 输出建议

- 如果用户没有明确子订单结构，不直接给细节代码，先要求补充业务模型。
- 若只是问“是否支持合单”，先解释适用条件和差异点，再决定是否进入代码阶段。
