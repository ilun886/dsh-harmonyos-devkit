# 签名与验签规则

## 核心原则

- `orderStr` 与 `contractStr` 必须由服务端生成。
- 客户端不得自己拼装签名串，也不得本地 Mock 签名。
- 请求签名与回调验签是两条链路，都必须正确。

## 请求签名

### 通用规则

- 参与签名前排除 `sign` 字段。
- 参数按 key 的 ASCII 顺序排序。
- 使用 `k=v` 形式并以 `&` 连接。
- `null` 可按接口要求不参与；空字符串必须按原样参与。
- 同一业务请求应使用唯一流水或唯一 `traceId`，避免重复请求。

### 算法

- 常见算法：`SHA256WithRSA/PSS` 或 `SM2`
- 实际以商户当前证书体系和官方接口要求为准。

### SDK 场景

若服务端使用 Java SDK：
- 优先复用 SDK 自动签名能力。
- 不重复手写请求签名逻辑，避免与 SDK 行为不一致。

## 回调验签

### 顺序要求

1. 接收回调原始报文。
2. 使用华为支付公钥先验签。
3. 验签成功后再反序列化并执行业务处理。
4. 业务处理必须幂等。
5. 返回成功应答。

### 禁止事项

- 先转对象再验签。
- 验签失败仍继续更新订单状态。
- 只依赖客户端结果，不校验服务端回调。

## 成功应答

```json
{"resultCode":"000000","resultDesc":"Success."}
```

## 典型问题

- `INVALID_SIGNATURE`：优先检查排序、拼接、空值处理、公私钥是否匹配。
- 只有部分请求失败：优先检查是否复用了订单号、时间戳或随机串。
- 回调一直重试：优先检查是否真的返回了标准成功报文，以及是否在 3 秒内返回。
