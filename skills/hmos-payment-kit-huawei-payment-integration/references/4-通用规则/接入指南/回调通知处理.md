# 回调通知处理

## 处理顺序

1. 接收原始回调请求。
2. 先验签。
3. 验签通过后转业务对象。
4. 按订单号、回调唯一标识或 `callbackId` 做幂等控制。
5. 业务处理完成后返回标准成功报文。

## 成功应答

```json
{"resultCode":"000000","resultDesc":"Success."}
```

## 时效要求

- 商户服务端需要在 3 秒内返回结果。
- 未按时返回或返回内容不符合要求，会触发华为支付重试。
- 同一条通知可能被重复推送，必须按幂等设计处理。

## 业务约束

- 客户端支付成功回调不是最终交易结果，最终以服务端回调或查单为准。
- 验签失败不得更新任何订单状态。
- 业务处理要做到“可重试但不重复扣减、不重复发货、不重复入账”。

## Java SDK 示例来源

### 验签入口

本地服务端示例使用：
- `VerifyTools.getCallbackResult(...)` 处理回调验签。

### 配置注意

- 示例中的回调公钥不要使用空字符串占位。
- 实际项目应从配置中加载华为支付回调验签公钥，并和商户环境保持一致。

## 自检清单

- 回调 URL 是否为公网 HTTPS 地址。
- 是否先验签再转对象。
- 是否记录原始回调体与业务流水，方便排障。
- 是否对重复通知直接返回成功。
- 是否把支付、签约、退款、合单等不同通知映射到正确实体。
